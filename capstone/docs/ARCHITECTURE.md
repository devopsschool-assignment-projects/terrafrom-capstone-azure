# Application architecture

## The big picture

```
                         Internet
                            |
        app.student03.lab.collabgigs.com
                            |
   Cloudflare (registrar)   |  4 NS records: student03.lab -> Azure DNS
                            v
                   Azure DNS zone  student03.lab.collabgigs.com
                            |  A record  app -> Application Gateway public IP
                            v
 +--------------------------+--------------------------------------------+
 | Resource group rg-cap-student03          VNet 10.3.0.0/16              |
 |                                                                         |
 |  [ snet-appgw 10.3.1.0/24 ]                                            |
 |    Application Gateway (WAF_v2, OWASP 3.2)  <- blocks SQLi, XSS, ...   |
 |            |                                                            |
 |            v  private IP 10.3.0.100                                     |
 |  [ snet-aks 10.3.0.0/24 ]                                              |
 |    internal Azure Load Balancer  (created by the Kubernetes Service)    |
 |            |                                                            |
 |    AKS cluster (1 node)  namespace "capstone"                           |
 |      frontend (nginx) --> backend (Flask) --> postgres (StatefulSet)    |
 |                              |                      |                   |
 |                              |                 Azure Disk (5 GiB PVC)   |
 |                              +--> Key Vault  (Entra ID workload identity)|
 |                                                                         |
 |  Container Registry (images)   Storage Account (db-backups container)   |
 +--------------------------------------------------------------------------+
```

## Request flow

1. Browser asks DNS for `app.student03.lab.collabgigs.com`. Cloudflare says
   "ask Azure DNS" (the NS records), Azure DNS returns the Application Gateway IP.
2. The **Application Gateway** receives the HTTP request. The **WAF** inspects it and
   blocks attacks (returns 403).
3. Clean requests go to the **internal load balancer** (fixed private IP) and on to a
   **frontend** pod (nginx).
4. nginx serves the web page, and forwards `/api/...` to the **backend** service.
5. The **backend** reads/writes **PostgreSQL**. The database runs *inside* the cluster
   as a StatefulSet; its data is stored on an **Azure Disk**.
6. The backend reads the page banner from **Key Vault** using its own **Entra ID identity**.

## Identity and secrets (no passwords in code)

| Who | Identity | Can do |
|---|---|---|
| AKS control plane | user-assigned managed identity | manage the VNet (internal load balancer) |
| AKS nodes (kubelet) | kubelet managed identity | pull images from ACR (`AcrPull`) |
| Backend pod | user-assigned identity + federated credential | read Key Vault secrets (`Key Vault Secrets User`) |
| You (deployer) | your Entra ID account | write secrets, use `kubectl` (`Cluster Admin` role) |

How the pod proves who it is: Kubernetes issues the pod a signed token. Entra ID trusts
tokens from this cluster's OIDC issuer for exactly one service account
(`system:serviceaccount:capstone:backend`) through a **federated credential**. No secret is stored.

The database password is generated by Terraform, stored in Key Vault and placed in a
Kubernetes Secret for the database and backend pods.

## Terraform structure

```
config/master-values.yaml  --(yamldecode)-->  infra/main.tf  (root module)
                                                  |
   network -> identity -> aks -> workload-identity -> k8s-app -> appgw -> dns
   acr, keyvault, storage (independent)         build-images (script) runs before k8s-app
```

* One **root module**, ten **child modules**, every value passed in from the root.
* **One state file per student** in Azure Storage (`student03.tfstate`), so 12 students can
  deploy at the same time without touching each other.
* Names are `<prefix>-<student>`; globally unique names get a 4-letter random suffix.
* Each student gets their own IP range: `10.<index>.0.0/16`.

## Design choices (and why)

| Choice | Why |
|---|---|
| App Gateway -> **internal** LB -> pods | Shows a real WAF + load balancer path, with no circular dependency between gateway and cluster |
| PostgreSQL **in the cluster** | Requirement: no managed database; also teaches StatefulSets and PVCs |
| HTTP only | Keeps the lab simple. Adding HTTPS is a stretch exercise |
| Cluster has **local admin enabled** | Terraform uses it to deploy the app. Students use their Entra login for `kubectl` |
| Key Vault purge protection **off** | Lab only - lets you destroy and redeploy with the same names |
| 1 node, `Standard_D2s_v6` | Cost and quota. Requests are small so DB + backend + frontend fit |
